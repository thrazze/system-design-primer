# Часть A. Проект: русский vault

## A0. Что уже есть на русском — и чего нет

Проверил оба существующих перевода. Вывод неприятный, но полезный: **они обрываются практически в одном и том же месте.**

| Источник | Докуда дошёл | Покрытие README | Задачи |
|---|---|---|---|
| Google Doc (Ольховой Д.Р.), 65 КБ | до конца NoSQL (графовые БД), дальше — голый список ссылок | ~38 % | 0 из 8 |
| [voitau/README-ru.md](https://github.com/voitau/system-design-primer/blob/master/README-ru.md), 89 КБ | до заголовка `## Database`, тело раздела не переведено | ~32 % | 0 из 8 |

**Никем не переведено вообще:**

| Раздел | Объём | Почему это больно |
|---|---|---|
| Cache | 8.6 КБ | Ядро почти любого дизайна |
| Asynchronism | 3.2 КБ | Очереди, back pressure |
| Communication (HTTP/TCP/UDP/RPC/REST) | 12.3 КБ | Спрашивают всегда |
| Security | 1.0 КБ | |
| Appendix (цифры, реальные архитектуры) | 20.0 КБ | Те самые цифры, что надо знать наизусть |
| Study guide + How to approach + Index | 9.5 КБ | Вся методика |
| **Все 8 разборов задач** | **134 КБ** | Самая ценная часть Primer |

Итого непокрыто: **~55 КБ README + 134 КБ решений = ~190 КБ**, то есть **около 80 % полезного объёма репозитория**.

### Что берём из перевода коллег

Не как основу, а как три конкретные вещи:

1. **Сверку терминологии** — где их вариант лучше моего, беру их. Уже учтено в [[Глоссарий]].
2. **Бонусный материал, которого в Primer нет:** в Google Doc целиком переведена статья Мартина Фаулера о микросервисах (закон Конвея, smart endpoints/dumb pipes, децентрализованное управление, design for failure, эволюционный дизайн). Это ~15 КБ хорошего текста мимо Primer — переношу отдельной заметкой `Микросервисы (Фаулер)`.
3. **Список известных ошибок, которые не надо повторять** — см. конец [[Глоссарий]]. Главные: `fail-over` переведён как «отказоустойчивость» (это `fault tolerance`, другое понятие), «кеш»/«кэш» вперемешку, `consistency` то «согласованность», то «консистентность».

**Почему не берём как основу перевода:** текст лежит в Google Docs без структуры заголовков, без ссылок, с потерянными картинками и кусками таблиц. Привести его к формату vault'а дороже, чем перевести заново с английского оригинала по фиксированному глоссарию. Оригинал — единственный источник, который гарантированно полон и актуален.

## A2. Формат заметки — утверждён на пилоте

Смотри [[Кэш]] рядом с [[Cache]]. Структура RU-заметки:

```
frontmatter: lang / en: "[[Cache]]" / tags / status
> 🇬🇧 Оригинал: [[Cache]] · 🗺 Карта · 📖 Глоссарий

<перевод, заголовки 1-в-1 с оригиналом>

🧠 Своими словами    ← пустой, заполняешь ты. Главная часть заметки
❓ Самопроверка       ← 4–6 вопросов, часть из них — за пределами Primer
🔗 Связано           ← wiki-ссылки на смежные темы
```

Ключевое решение: **перевод — это не конечный продукт, а подложка.** Ценность появляется в блоке «Своими словами», который пишешь ты. Поэтому он есть в каждой заметке и в `status` есть отдельное значение `освоено` — отличное от `переведено`.

## A5. Синхронизация на телефон — бесплатно, через git

Vault уже лежит внутри git-репозитория форка, поэтому платный Obsidian Sync не нужен — синхронизация приложена бесплатно к тому, что уже есть.

**Десктоп.** В Obsidian: `Settings → Community plugins → Browse → Obsidian Git` → включить. Затем `Settings → Obsidian Git`:
- Auto-commit: включить, интервал 10 мин
- Auto push: включить (или коммить/пушить вручную командой `Obsidian Git: Commit and push` через Ctrl/Cmd+P)

**Телефон.**

| ОС | Что поставить | Как |
|---|---|---|
| iOS | [Working Copy](https://workingcopyapp.com/) (бесплатно с ограничением в 1 репозиторий — как раз наш случай) | Клонировать `https://github.com/thrazze/system-design-primer.git`, открыть Obsidian, `Settings → Files & links → выбрать хранилище` → указать папку внутри Working Copy. Установить плагин Obsidian Git и там тоже — он использует Working Copy как git-провайдер |
| Android | [MGit](https://github.com/maks/MGit) или Termux + git — оба бесплатны | Клонировать репозиторий в доступную Obsidian папку, дальше так же ставить Obsidian Git в мобильном Obsidian |

**Ежедневный цикл:** перед началом занятия — pull, после — commit & push. Плагин Obsidian Git умеет делать это автоматически по таймеру, вручную дёргать не обязательно.

**Конфликты.** Если правил на двух устройствах офлайн одновременно, будет обычный git-конфликт в `.md`-файле — маркеры `<<<<<<<` прямо в тексте. Решается как обычный merge conflict в любом git-клиенте.

# Часть B. Маршрут обучения — 12 недель

10–12 ч/нед. Недели 8–11 важнее 1–7: **если время поджимает, режь теорию, не практику.**

## Как учиться

Primer — справочник, а не учебник. Читать подряд бесполезно. Работает обратный ход:

> задача → упёрся в незнание → идёшь в нужную заметку → возвращаешься и достраиваешь дизайн

Три правила на все 12 недель:

1. **Всё вслух.** Дизайн, который не проговорил, — не выученный дизайн.
2. **Всё на бумаге.** Не в Excalidraw. На собесе будет доска или примитивный редактор.
3. **Цифры всегда.** Без оценки нагрузки это не дизайн, а список коробочек.

И главное: заметка считается пройденной не когда переведена, а когда в ней заполнен блок **🧠 Своими словами**. Ставь `status: освоено`.

## Недели 4–7. Компоненты вглубь

**Неделя 4 — кэш.** [[Кэш]]
Для каждой стратегии: что теряется при падении кэша и при падении БД. Что такое cache stampede и три способа лечить. Как инвалидировать ленту, если аватар сменил пользователь с 10 млн подписчиков.

**Неделя 5 — асинхронность.** [[Асинхронность]]
At-least-once vs at-most-once vs exactly-once, идемпотентность потребителя. Спроектируй outbox pattern. Что делать с dead letter queue.

**Неделя 6 — коммуникации.** [[Коммуникации]] · [[Протокол HTTP]] · [[TCP и UDP]] · [[RPC и REST]] · [[Безопасность]]
Практика: реализуй распределённый token bucket rate limiter на Redis — частый follow-up на собесе. Три сценария: когда WebSocket, когда SSE, когда long polling.

**Неделя 7 — расчёты.** [[Расчёты на салфетке]] · [[Цифры, которые надо знать наизусть]]
Выучить наизусть: L1 0.5 нс, RAM 100 нс, SSD random read 150 мкс, round trip в ДЦ 0.5 мс, диск seek 10 мс, CA↔NL 150 мс, суток ≈ 86 400 с (10⁵), 1 млн запросов/день ≈ 12 RPS.
Три упражнения по 10 минут вслух: хранилище Твиттера на 5 лет; сколько серверов на 10M DAU при 20 запросах и 1000 RPS на сервер; память под кэш горячих 20 %.

## Пять ошибок, которые убивают собес

1. **Сразу рисовать схему.** Без требований и цифр это видно в первые 5 минут.
2. **Называть технологии вместо ролей.** Не «поставлю Kafka», а «поставлю очередь с сохранением порядка внутри партиции — например, Kafka».
3. **Молчать, пока думаешь.** Оценивают ход мысли. Тишина = нечего оценивать.
4. **Проектировать идеально.** Правильный ответ — простейшая система под требования + план масштабирования. Микросервисы на 1000 пользователей — красный флаг.
5. **Не задавать вопросов.** Задача размыта намеренно. Уточнение скоупа — часть оценки.
