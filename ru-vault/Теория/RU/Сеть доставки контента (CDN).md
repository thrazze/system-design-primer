# Сеть доставки контента (CDN)

<p align="center">
  <img src="../../../images/h9TAuGI.jpg">
  <br/>
  <i><a href=https://www.creative-artworks.eu/why-use-a-content-delivery-network-cdn/>Источник: Why use a CDN</a></i>
</p>

Сеть доставки контента (CDN) — это глобально распределённая сеть прокси-серверов, которая отдаёт контент из точек, географически близких к пользователю. Обычно через CDN раздают статику: HTML/CSS/JS, фотографии, видео, хотя некоторые CDN, например Amazon CloudFront, умеют отдавать и динамический контент. Какой именно сервер использовать, клиенту подскажет DNS-резолюция сайта.

Раздача контента через CDN заметно повышает производительность по двум причинам:

* Пользователи получают контент из дата-центров, расположенных рядом с ними
* Вашим серверам не приходится обрабатывать запросы, которые закрывает CDN

### Push CDN

Push CDN получает новый контент каждый раз, когда на вашем сервере что-то меняется. Вы полностью отвечаете за поставку контента: загружаете его на CDN напрямую и переписываете URL так, чтобы они указывали на CDN. Можно настроить, когда контент считается устаревшим и когда его нужно обновлять. Контент загружается только тогда, когда он новый или изменился, — это минимизирует трафик, но увеличивает расход хранилища.

Push CDN хорошо подходит сайтам с небольшим трафиком или с контентом, который обновляется редко. Контент размещается на CDN один раз, вместо того чтобы регулярно перезапрашиваться.

### Pull CDN

Pull CDN забирает новый контент с вашего сервера, когда его запрашивает первый пользователь. Контент остаётся на вашем сервере, а URL переписываются так, чтобы указывать на CDN. Из-за этого первый запрос — до того как контент попадёт в кэш CDN — выполняется медленнее.

[TTL (time-to-live)](https://en.wikipedia.org/wiki/Time_to_live) определяет, как долго контент хранится в кэше. Pull CDN экономит место на самой CDN, но может создавать избыточный трафик, если файлы устаревают и перезапрашиваются раньше, чем реально изменились.

Pull CDN хорошо подходит сайтам с большим трафиком: нагрузка распределяется более равномерно, а на CDN остаётся только недавно запрошенный контент.

### Недостатки: CDN

* Расходы на CDN могут оказаться значительными в зависимости от трафика, хотя их стоит сравнивать с дополнительными издержками, которые возникли бы без CDN.
* Контент может оказаться устаревшим, если его обновили на сервере до истечения TTL.
* Для CDN приходится менять URL статического контента, чтобы они указывали на CDN.
