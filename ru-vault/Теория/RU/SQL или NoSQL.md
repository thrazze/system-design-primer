# SQL или NoSQL

<p align="center">
  <img src="../../../images/wXGqG5f.png">
  <br/>
  <i><a href=https://www.infoq.com/articles/Transition-RDBMS-NoSQL/>Источник: Transitioning from RDBMS to NoSQL</a></i>
</p>

Причины выбрать **SQL**:

* Структурированные данные
* Строгая схема
* Реляционные данные
* Нужны сложные join'ы
* Транзакции
* Понятные пути масштабирования
* Зрелость: разработчики, сообщество, готовый код, инструменты и т. д.
* Поиск по индексу работает очень быстро

Причины выбрать **NoSQL**:

* Полуструктурированные данные
* Динамическая или гибкая схема
* Нереляционные данные
* Сложные join'ы не нужны
* Хранение многих терабайт (или петабайт) данных
* Профиль нагрузки с очень интенсивной работой с данными
* Очень высокая пропускная способность по IOPS

Примеры данных, которые хорошо ложатся на NoSQL:

* Быстрый приём потоков кликов и логов
* Таблицы лидеров и очки игроков
* Временные данные — например, корзина покупок
* Часто запрашиваемые («горячие») таблицы
* Таблицы метаданных и справочники
