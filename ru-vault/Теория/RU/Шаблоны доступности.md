# Шаблоны доступности

Высокую доступность обеспечивают два взаимодополняющих шаблона: **переключение при отказе (fail-over)** и **репликация**.

## Переключение при отказе (fail-over)

### Активный-пассивный

При схеме «активный-пассивный» активный сервер и пассивный сервер в резерве обмениваются сигналами heartbeat. Как только сигнал прерывается, пассивный сервер забирает себе IP-адрес активного и продолжает обслуживать запросы.

Длительность простоя зависит от того, работает ли пассивный сервер в «горячем» резерве или его нужно поднимать из «холодного». Трафик обрабатывает только активный сервер.

Активный-пассивный вариант переключения при отказе также называют master-slave failover.

### Активный-активный

При схеме «активный-активный» трафик обрабатывают оба сервера, деля нагрузку между собой.

Если серверы смотрят наружу, DNS должен знать публичные IP-адреса обоих. Если они внутренние — про оба сервера должна знать логика приложения.

Активный-активный вариант переключения при отказе также называют master-master failover.

## Недостатки: переключение при отказе

* Переключение при отказе означает лишнее железо и дополнительную сложность.
* Есть риск потерять данные: активная система может упасть раньше, чем свежезаписанные данные успеют реплицироваться на пассивную.

## Доступность в цифрах

Доступность обычно выражают через uptime (или downtime) — долю времени, когда сервис работает. Меряют её количеством девяток: сервис с доступностью 99.99% описывают как «четыре девятки».

### Доступность 99.9% — три девятки

| Период              | Допустимый простой |
|---------------------|--------------------|
| Простой за год      | 8 ч 45 мин 57 с    |
| Простой за месяц    | 43 мин 49.7 с      |
| Простой за неделю   | 10 мин 4.8 с       |
| Простой за сутки    | 1 мин 26.4 с       |

### Доступность 99.99% — четыре девятки

| Период              | Допустимый простой |
|---------------------|--------------------|
| Простой за год      | 52 мин 35.7 с      |
| Простой за месяц    | 4 мин 23 с         |
| Простой за неделю   | 1 мин 5 с          |
| Простой за сутки    | 8.6 с              |

### Доступность при параллельном и последовательном соединении

Если сервис собран из нескольких компонентов, каждый из которых может отказать, итоговая доступность зависит от того, соединены компоненты последовательно или параллельно.

##### Последовательно

Когда два компонента с доступностью < 100% стоят последовательно, общая доступность падает:

```
Availability (Total) = Availability (Foo) * Availability (Bar)
```

Если у `Foo` и у `Bar` доступность по 99.9%, то последовательно их суммарная доступность составит 99.8%.

##### Параллельно

Когда два компонента с доступностью < 100% стоят параллельно, общая доступность растёт:

```
Availability (Total) = 1 - (1 - Availability (Foo)) * (1 - Availability (Bar))
```

Если у `Foo` и у `Bar` доступность по 99.9%, то параллельно их суммарная доступность составит 99.9999%.
