# Каркас ответа на собеседовании

> Как подступиться к задаче на проектирование системы.

Собеседование по системному дизайну — это **разговор без единственно верного ответа**. Вести его должен ты.

Ниже — шаги, по которым удобно строить обсуждение. Чтобы каркас закрепился, прогоняй по этим шагам задачи из раздела с разборами.

## Шаг 1: Обозначь сценарии использования, ограничения и допущения

Собери требования и очерти границы задачи. Задавай вопросы, чтобы прояснить сценарии использования и ограничения. Проговори допущения.

* Кто этим будет пользоваться?
* Как именно они будут этим пользоваться?
* Сколько пользователей?
* Что делает система?
* Что у системы на входе и что на выходе?
* Какой объём данных ожидаем?
* Сколько запросов в секунду ожидаем?
* Какое ожидается соотношение чтений и записей?

## Шаг 2: Набросай высокоуровневую схему

Опиши архитектуру крупными мазками — со всеми важными компонентами.

* Нарисуй основные компоненты и связи между ними
* Обоснуй свои решения

## Шаг 3: Спроектируй ключевые компоненты

Погрузись в детали каждого ключевого компонента. Например, если тебя просят [спроектировать сервис сокращения ссылок](solutions/system_design/pastebin/README.md), обсуди:

* Генерацию и хранение хеша полного URL
    * [MD5](solutions/system_design/pastebin/README.md) и [Base62](solutions/system_design/pastebin/README.md)
    * Коллизии хешей
    * SQL или NoSQL
    * Схему базы данных
* Обратное преобразование хеша в полный URL
    * Поиск в базе данных
* API и объектно-ориентированный дизайн

## Шаг 4: Масштабируй решение

Найди узкие места и разберись с ними — с оглядкой на ограничения. Например, нужно ли что-то из этого, чтобы снять проблемы с масштабируемостью?

* Балансировщик нагрузки
* Горизонтальное масштабирование
* Кэширование
* Шардирование базы данных

Обсуждай варианты решений и компромиссы. Компромисс есть везде. Узкие места разбирай, опираясь на принципы проектирования масштабируемых систем.
