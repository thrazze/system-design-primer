### Сценарий: пользователь отправляет запрос, который приводит к попаданию в кэш

Популярные запросы можно отдавать из **Memory Cache** — например, Redis или Memcached, — чтобы снизить задержку чтения и не перегружать **Reverse Index Service** и **Document Service**. Последовательное чтение 1 MB из памяти занимает около 250 микросекунд, тогда как чтение с SSD — в 4 раза дольше, а с диска — в 80 раз дольше.<sup><a href=https://github.com/donnemartin/system-design-primer#latency-numbers-every-programmer-should-know>1</a></sup>

Поскольку у кэша ограниченная ёмкость, применим подход least recently used (LRU) для вытеснения старых записей.

* **Client** отправляет запрос на **Web Server**, работающий как [[Обратный прокси|обратный прокси]]
* **Web Server** перенаправляет запрос на сервер **Query API**
* Сервер **Query API** делает следующее:
    * Разбирает запрос
        * Удаляет разметку
        * Разбивает текст на термы
        * Исправляет опечатки
        * Нормализует регистр
        * Переводит запрос в булевы операции
    * Проверяет **Memory Cache** на наличие контента, подходящего под запрос
        * Если в **Memory Cache** есть попадание, **Memory Cache** делает следующее:
            * Перемещает кэшированную запись в начало LRU-списка
            * Возвращает кэшированное содержимое
        * Иначе **Query API** делает следующее:
            * Использует **Reverse Index Service**, чтобы найти документы, подходящие под запрос
                * **Reverse Index Service** ранжирует найденные результаты и возвращает лучшие из них
            * Использует **Document Service**, чтобы получить заголовки и сниппеты
            * Обновляет **Memory Cache** новым содержимым, помещая запись в начало LRU-списка

#### Реализация кэша

Кэш можно построить на двусвязном списке: новые элементы добавляются в голову, а вытесняемые — удаляются из хвоста. Для быстрого поиска узла связного списка используем хеш-таблицу.

**Уточни у интервьюера, сколько кода от тебя ожидают написать**.

Реализация **Query API Server**:

```python
class QueryApi(object):

    def __init__(self, memory_cache, reverse_index_service):
        self.memory_cache = memory_cache
        self.reverse_index_service = reverse_index_service

    def parse_query(self, query):
        """Remove markup, break text into terms, deal with typos,
        normalize capitalization, convert to use boolean operations.
        """
        ...

    def process_query(self, query):
        query = self.parse_query(query)
        results = self.memory_cache.get(query)
        if results is None:
            results = self.reverse_index_service.process_search(query)
            self.memory_cache.set(query, results)
        return results
```

Реализация **Node**:

```python
class Node(object):

    def __init__(self, query, results):
        self.query = query
        self.results = results
```

Реализация **LinkedList**:

Реализация **Cache**:

```python
class Cache(object):

    def __init__(self, MAX_SIZE):
        self.MAX_SIZE = MAX_SIZE
        self.size = 0
        self.lookup = {}  # key: query, value: node
        self.linked_list = LinkedList()

    def get(self, query)
        """Get the stored query result from the cache.

        Accessing a node updates its position to the front of the LRU list.
        """
        node = self.lookup[query]
        if node is None:
            return None
        self.linked_list.move_to_front(node)
        return node.results

    def set(self, results, query):
        """Set the result for the given query key in the cache.

        When updating an entry, updates its position to the front of the LRU list.
        If the entry is new and the cache is at capacity, removes the oldest entry
        before the new entry is added.
        """
        node = self.lookup[query]
        if node is not None:
            # Key exists in cache, update the value
            node.results = results
            self.linked_list.move_to_front(node)
        else:
            # Key does not exist in cache
            if self.size == self.MAX_SIZE:
                # Remove the oldest entry from the linked list and lookup
                self.lookup.pop(self.linked_list.tail.query, None)
                self.linked_list.remove_from_tail()
            else:
                self.size += 1
            # Add the new key and value
            new_node = Node(query, results)
            self.linked_list.append_to_front(new_node)
            self.lookup[query] = new_node
```

#### Когда обновлять кэш

Кэш нужно обновлять, когда:

* Меняется содержимое страницы
* Страница удаляется или добавляется новая
* Меняется ранг страницы (page rank)

Самый простой способ справиться с этим — задать максимальное время, которое запись может оставаться в кэше до обновления, то есть time to live (TTL).

Компромиссы и альтернативы см. в разделе [[Кэш|«Когда обновлять кэш»]]. Описанный выше подход — это [[Кэш|cache-aside]].

### Расширяем Memory Cache на много машин

Чтобы справиться с высокой нагрузкой по запросам и большим объёмом требуемой памяти, будем масштабироваться горизонтально. Есть три основных варианта хранения данных в кластере **Memory Cache**:

* **У каждой машины в кластере кэша — свой собственный кэш** — просто, но, скорее всего, даст низкий процент попаданий в кэш.
* **У каждой машины в кластере кэша — копия всего кэша** — просто, но неэффективно расходует память.
* **Кэш [[Реляционные БД (RDBMS)|шардирован]] по всем машинам кластера** — сложнее, но, скорее всего, лучший вариант. Можно использовать хеширование, чтобы определить, на какой машине лежат кэшированные результаты запроса: `machine = hash(query)`. Здесь, вероятно, стоит использовать консистентное хеширование.
